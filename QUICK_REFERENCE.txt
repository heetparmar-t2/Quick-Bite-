COMMON QUESTIONS & ANSWERS
┌─────────────────────────────────────────────────────────────────────────────┐
│ Q: How does the payment system work?
│ A: Students earn 1 point per rupee spent. Points are used to pay for future
│    orders. They scan a QR code to complete payment. Points deducted instantly.
│
│ Q: What's unique about this app?
│ A: The gamification system with points, tiers, and leaderboard increases
│    student engagement. The real-time KDS improves kitchen efficiency.
│
│ Q: Is this scalable?
│ A: Yes! Built on Supabase PostgreSQL and Vercel serverless. Can handle
│    1000s of concurrent orders with auto-scaling.
│
│ Q: How is it secure?
│ A: Uses Supabase Auth for email/password, Row-Level Security for data
│    isolation, and role-based access control (Student vs Admin).
│
│ Q: Can I customize it?
│ A: Absolutely! Menu items, prices, loyalty tiers, themes are all
│    customizable. Code is well-structured for easy modifications.
│
│ Q: How much time did it take?
│ A: Core features in 3-4 weeks. Full polish & testing in 1-2 weeks.
│    Ready for production in ~5-6 weeks total.

TROUBLESHOOTING QUICK FIXES
┌─────────────────────────────────────────────────────────────────────────────┐
│ Menu not showing?
│ → Run seed scripts in Supabase SQL Editor
│ → Check /api/menu endpoint returns data
│
│ Can't login?
│ → Verify demo@example.com exists in Supabase Auth
│ → Check password is correct: Demo@123
│ → User profile must exist in user_profiles table
│
│ Images not loading?
│ → Check /public/menu/ folder has images
│ → Verify image paths in menu_items table
│ → Use Ctrl+Shift+R to hard refresh
│
│ Payment fails?
│ → Check user has ≥ required points
│ → Verify order_items table accepts inserts
│ → Check sessionStorage for pending_order
│
│ Admin access denied?
│ → Verify admin user role = 'admin'
│ → Check RLS policies in Supabase
│ → Sign out and login again
│
│ Something crashed?
│ → Check browser console (F12) for errors
│ → Try hard refresh (Ctrl+Shift+R)
│ → Use preview mode as backup
